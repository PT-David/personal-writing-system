=========================

当前脚本：bili_watcher.py 0.3.8-access-refresh-optin
项目目录：D:\Program files\Telethon\bili_archive
Python：D:\Program files\Telethon\.venv\Scripts\python.exe

【速查排列原则】

本文件按实际运行顺序排列：

check-config
→ check-login / Cookie
→ init-db（首次）
→ sync / init / reconcile（作者变化时）
→ scan
→ download
→ status
→ FAILED / 媒体修复 / DownKyi
→ 权限与人工终态
→ 测试 / 帮助

因此从上往下查找即可；同一命令的常用参数仍集中放在该命令第一次出现的位置。

九、完整运行顺序
------------

【项目第一次建立 Watcher】

1. check-config
2. check-login
3. 登录失败时重新获取 Cookie / export-cookies
4. init-db
5. 确认作者初始化状态
6. scan --details
7. download --pending
8. status


【普通已有 UP 的日常更新】

1. check-config
2. check-login
3. scan --details
4. download --pending
5. status
6. 有 FAILED / 权限 / 媒体异常时进入对应异常命令
7. bili_archive.py scan

如果配置和 Cookie 长期稳定，实际日常运行时可以直接从 scan 开始；这里仍按完整检查顺序排列，方便很久以后重新启动项目时照着执行。


【新增 UP】

1. check-config
2. check-login
3. 建立作者文件夹 + 新建文本文档.txt
4. sync-creators
5. list-uninitialized（需要确认还有哪些作者未初始化时）
6. preview-creator（需要查看投稿、选择 BVID 基线时）
7. init-creator
8. scan --details
9. download --pending
10. status


【UP 改名】

1. sync-creators
2. 出现疑似同 UID 新旧目录时：reconcile-creators
3. 确认预览正确：reconcile-creators --apply
4. 不要重新 init-creator
5. 继续正常 scan → download → status


【下载失败】

1. status / status --bvid
2. download --retry-failed
3. 仍失败：查看日志
4. 可以人工取得视频：DownKyi → import-downkyi
5. 不再下载：skip-download
6. 已确认原投稿删除：mark-source-unavailable


【已经 STAGED / IMPORTED_DOWNKYI，但正式视频异常】

1. audit-media
2. repair-media --bvid BVxxxxxxxxxx
3. repair-media --bvid BVxxxxxxxxxx --apply
4. download --pending
5. status / audit-media 再确认
