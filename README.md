# 个人写作系统

在这里保存可复用的写作规范、案例和项目资料。每次写作只读取适用规范与当前任务需要的资料；写作中形成的新经验，经整理后更新相应规范包。

## 从哪里开始

- **写文章**：按下面的“开始写作”操作。
- **新建或维护规范包**：阅读 [规范包编写说明.txt](规范包编写说明.txt)。
- **在仓库中工作的 AI**：先阅读本页；[AGENTS.md](AGENTS.md) 提供操作入口。
- **接续未完成的仓库修改**：打开对应 PR，阅读说明、已有提交及最新差异，继续使用该分支。

## 内容放在哪里

- 根目录：本页、AI 操作指引、规范包编写说明。
- `规范包/<包名>/使用规则.txt`：适用范围、写作规则、必读补充和交稿检查，供写作 AI 阅读。
- `规范包/<包名>/规则依据.txt`：规则的来源与适用边界，供整理经验、解释或修改规则时查阅。
- `规范包/<包名>/补充/`：按实际需要增加的模板、专题说明或长案例。
- `项目资料/<项目名>/`：该项目的文稿、反馈、代码、来源或设定等材料，按项目分别保存。

目录随实际内容建立。不同文类可以保存不同材料；具体文件安排见编写说明。

## 已有规范包

暂无。新增规范包时，在这里补充包名、适用范围和“使用规则”链接。

## 开始写作

1. 提供本仓库链接、写作任务、目标读者，以及当前项目资料的位置。
2. AI 读取默认分支的本页，选择适用规范包，记录该分支的提交编号。此次所用规范文件读取同一提交版本。
3. AI 读取所选包的“使用规则”，以及其中明确列出的本次必读补充；再读取与任务相关的项目资料。历史项目与“规则依据”在需要查证案例或规则来源时读取。
4. AI 简要说明实际采用的规范包和版本，随后写作，并按包内要求检查稿件。用户对当前任务的明确要求优先；实际存在的冲突需要说明。

尚无适用规范包时，依据用户要求完成写作，再用真实反馈整理经验。不要套用不适用的包，也不要预先生成其他文类的整套规则。

可复制以下指令到写作对话，补齐方括号内容：

> 请读取 https://github.com/PT-David/personal-writing-system 的 README.md，按“开始写作”使用适用规范。任务：[写什么、给谁看、需要什么输出]。当前项目资料：[文件、链接或本对话已提供的材料]。

仓库链接本身不会让 AI 自动读取文件。需要确认所用对话能访问仓库并取得文件正文。读取失败时，说明缺少的文件；由用户提供这些文件的文本或附件后继续。临时副本注明仓库路径及版本，后续修改回到仓库中的对应文件。

## 把经验补回仓库

先在有写作上下文的对话中明确要保留的经验，再让有仓库写入能力的 AI 按编写说明更新相关文件。一次已讨论清楚的修改使用一个工作分支和一个 PR；验收中的补改继续放在同一 PR，由用户合并。

可使用以下指令：

> 请读取 https://github.com/PT-David/personal-writing-system 的 README.md 和规范包编写说明.txt，根据本对话已确认的写作经验，创建或更新适用规范包。同步相关项目依据，检查后提交一个 PR，由我合并。

如果当前对话无法写入仓库，由它整理完整的改动内容、理由、相关材料及对应路径，交给能写入的对话执行。承接对话沿用已确认的结论；缺少依据时说明缺项。

默认分支保存已合并内容。历史修改由 Git 提交和 PR 保存；文件沿用固定路径，避免反复保存整套版本副本。中断时把进度、待办及必要的决策背景写在对应 PR 中，续接后继续该分支。
